# Trello 式看板应用实施计划（React + Vite + TS + Tailwind v4 + @dnd-kit + sql.js + OPFS）

## 1. 项目脚手架
- 在 `D:\zcodework\trello` 中 `npm create vite@latest . -- --template react-ts`
- 安装：`tailwindcss @tailwindcss/vite`（Tailwind v4 走 Vite 插件，无需 config）、`@dnd-kit/core @dnd-kit/sortable @dnd-kit/utilities`、`sql.js`（+ `@types/sql.js` devDep）
- `vite.config.ts` 注册 `@tailwindcss/vite`；`index.css` 写 `@import "tailwindcss";` + 少量自定义样式（滚动条、拖拽阴影）

## 2. 数据层：sql.js + OPFS（Web Worker）

**表结构**（首次运行建库并写入中文种子看板）：
```sql
boards(id TEXT PK, title TEXT, position REAL, created_at TEXT)
lists (id TEXT PK, board_id TEXT→boards, title, position REAL, created_at)
cards (id TEXT PK, list_id TEXT→lists, title, description TEXT DEFAULT '', position REAL, created_at)
-- PRAGMA foreign_keys=ON，board/list 删除时级联清理
```

**`src/db/worker.ts`** — 数据库 Worker（Vite 原生 Worker 打包）：
- `initSqlJs({ locateFile: () => wasmUrl })`（`sql.js/dist/sql-wasm.wasm?url` 导入）
- OPFS：`navigator.storage.getDirectory()` → `getFileHandle('trello.sqlite', {create:true})` → `createSyncAccessHandle()`
- 有文件则读字节恢复 `new SQL.Database(bytes)`；否则建表 + 种子数据
- 消息协议（自增 id 的 request/response）：`query`（返回行数组）/ `exec`（写后立即持久化）
- 持久化：`truncate(0)` → `write(db.export(), {at:0})` → `flush()`；同步句柄在 Worker 内合法，不阻塞主线程，库文件小、全量写可接受
- OPFS 不可用/句柄被占用（多标签页）时上报错误，主线程显示错误横幅

**`src/db/client.ts`** — Worker 通信封装为 Promise（pending map by id）
**`src/db/repo.ts`** — 类型化数据访问：listBoards / getBoardData / 各实体 CRUD / moveCard / moveList；id 用 `crypto.randomUUID()`；拖拽落位时对受影响序列按 1024 间隔重编 position，只更新变动行

## 3. 前端状态与组件

**状态**：`src/hooks/useKanban.ts`，不引额外状态库——加载 boards + 当前看板数据；每次变更先本地乐观更新再写库，失败回滚并提示

**组件树**：
```
App.tsx          — 初始化 loading / 错误横幅
TopBar.tsx       — 看板切换下拉、新建看板、当前看板重命名/删除
BoardView.tsx    — DndContext + DragOverlay，水平滚动列表容器
ListColumn.tsx   — 可排序列 + 卡片 droppable 容器 + 列内 SortableContext
KanbanCard.tsx   — 可排序卡片
CardComposer.tsx — 列底部"添加卡片"表单
ListComposer.tsx — 看板末尾"添加列表"表单
CardModal.tsx    — 卡片详情弹窗：编辑标题/描述、删除
```

**拖拽（@dnd-kit）**：
- 单一 DndContext；PointerSensor（5px 激活距离，避免误触点击）+ TouchSensor；closestCorners 碰撞检测
- `data.current.type` 区分 `card` / `list`
- 列内 SortableContext（垂直）+ 列作为 droppable 容器实现跨列移动；`onDragOver` 中卡片跨列时即时更新本地 state
- `onDragEnd` 计算最终顺序 → repo 批量写 position；列排序用 horizontalListSortingStrategy
- DragOverlay 渲染拖拽中的卡片/列（轻微倾斜 + 阴影），原位保留占位

**UI**：Trello 风格——蓝色顶栏、灰蓝背景、白色圆角卡片、半透明列背景、hover 阴影、列内独立纵向滚动；中文界面文案
